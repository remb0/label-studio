# Interface translation

Label Studio supports Dutch (`nl`), English (`en`), German (`de`), French (`fr`) and Spanish (`es`). `src/lib/i18n.ts` remains the single translation and language preference API. The expanded UI catalog lives in `src/lib/locales/*.json`; the original navigation/account keys remain compatible.

- Subscribe in React with `useT()`. Use `tx(key, { name, count })` for a complete sentence rather than translating concatenated fragments. Existing UI copy is used as a stable source key for the migrated screens; parameterized messages have named keys.
- Add every key to **all five** catalogs. Do not implement `language === "nl" ? ... : English` branches. `npm test` checks key parity, nonempty strings, matching placeholders, static references and dynamic metadata (commands, templates, printer evidence, address fields and formats).
- Keep dynamic messages in state as `UiMessage` descriptors using `message()` and `messageList()`. Throw `LocalizedError` for parameterized validation errors and retain metadata with `errorMessage()` at asynchronous boundaries. Rendering through `tx()` lets an existing error switch language without repeating a printer operation. Unknown platform errors retain technical detail inside a translated failure message.
- Use `formatDate`, `formatRelativeTime`, `formatNumber` and `useNumberFormatter` for display. Numeric input values, IDs, CSV values, document dimensions and exported JSON remain machine-readable. Dates use the selected locale and the user's local timezone; ISO dates in source evidence are interpreted as local calendar dates.
- The existing `label-studio:lang` preference is preserved. Valid saved language wins, then supported browser language, then English. Storage failure does not block in-memory switching. Unknown message keys fall back to English, then the key.

A language switch changes the interface, not the user's artwork, saved label names, CSV headers, address data, printer identifiers, connection protocols, calibration or favorites. Starter template artwork is example document content; its name, category and description in the template picker are translated. Diagnostic protocol values and third-party error details remain technical data. The optional account stays optional and makes no cloud requests when unconfigured.

## Validation

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`tests/e2e/i18n.spec.ts` runs editor, settings, CSV mapping, address validation, calibration, connection dialogs and offline guest account checks in all five languages. It also checks live switching, error/date localization, draft recovery, invalid language fallback and blocked storage. The existing browser regressions retain their behavioral assertions with Dutch selectors updated for the translated editor.

If Chromium is already installed elsewhere, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to its executable. Without that variable Playwright uses its normal managed browser. Production-container and documentation-screenshot tests retain their existing opt-in conditions. Tests use simulated Bluetooth; no physical printer certification is implied.
